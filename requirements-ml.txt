# Phase-3 onward only.  Install on top of requirements.txt:
#
#     pip install torch --index-url https://download.pytorch.org/whl/cu128
#     pip install -r requirements.txt -r requirements-ml.txt
#
# **Phases 0-2 never need this file.**  The deterministic core (`graft.core`),
# the enumerable environment and the exact evaluator (`graft.synth`) run on a
# bare interpreter, which is what keeps the suite runnable inside a Kaggle
# notebook before any heavy install and what
# `test_the_phase_0_to_2_surface_imports_no_ml_library` enforces.
#
# **The CUDA build is not incidental here.**  This project's GPU is Blackwell
# (RTX 50-series, compute capability sm_120), and sm_120 kernels first ship in
# the cu128 wheels.  A cu124 build installs cleanly, imports cleanly, reports
# `torch.cuda.is_available() == True`, and then fails at the first kernel launch
# -- so "torch is installed" is not the check.  The check is:
#
#     python -c "import torch; a=torch.randn(8,8,device='cuda'); print((a@a).sum())"
#
# Verified on this machine: torch 2.11.0+cu128, sm_120 present in
# `torch.cuda.get_arch_list()`, matmul executes.
#
# Pinned rather than floating, for the same reason every other version here is:
# `runtime.run_manifest` records package versions, and a floating pin makes two
# machines' manifests differ for reasons nobody chose.  The index URL stays out
# of this file because it is per-machine -- a CPU-only laptop or a Kaggle T4
# needs a different one, and hard-coding cu128 would make the file unusable
# there.

torch==2.11.0

# Phase 6 (Stage B) — added 14 Aug 2026.
#
# `torch_geometric` supplies E2's HGTConv (Phase-6 decision 1, gap G2).  The
# boring-stack rule (architecture 0.4) wants a written justification and this
# is it: HGT's node- and edge-type-dependent attention with relative temporal
# encoding is the *point of comparison* E2 exists to provide (HGT, WWW 2020),
# and hand-rolling typed attention is a correctness risk in exactly the place a
# subtle bug masquerades as "the baseline is weak" -- the failure mode Phase 3's
# capacity-match defect already demonstrated in this project.
#
# **Installed pure-Python, and that is a condition rather than an accident**:
# no `pyg_lib`, no `torch_scatter`.  Since PyG 2.3 the core message-passing
# classes run on plain torch, and the compiled extensions have no reliable
# Windows wheels.  Verified on this machine, 14 Aug 2026:
#
#     HGTConv forward AND backward execute; WITH_PYG_LIB=False,
#     WITH_TORCH_SCATTER=False
#
# `graft.graphbuild.encoders.hgt_available()` re-runs that check at import time,
# and E2 falls back to CompGCN (ICLR 2020, the architecture's named alternate)
# on plain torch if it ever fails -- recorded as a departure, never silent.
#
# E1 (the mandatory GraphMixer-style baseline) imports none of this, so the
# baseline survives any PyG breakage.
#
# `xxhash` is torch_geometric 2.8's own hard import (`hash_tensor`), not a
# GRAFT choice; pinned so the manifest does not move for a reason nobody picked.
torch_geometric==2.8.0.post1
xxhash==4.0.0

# Phase 7 (Stage C) — added 15 Aug 2026.
#
# `bm25s` is the BM25 channel (Phase-7 decision 1, gap G2).  The boring-stack
# rule (architecture 0.4) wants a written justification and this is it, in two
# parts.
#
# **It is the boring-stack shape, verified rather than assumed.**  Installed on
# this machine 15 Aug 2026: one pure-Python wheel, `numpy` its only runtime
# dependency -- *no scipy*, no index server, no persistence daemon, no
# background process.  The index is built in memory from a list of strings and
# thrown away with the process, which is what §7's "no ANN index, vector
# database or search server" is actually protecting.
#
# **Hand-rolling it would weaken a control.**  BM25 is a *baseline channel*, and
# R13's catalogue of this project's own defects is that three control bugs all
# ran in the direction that flattered the proposed method (`PHASE3_DECISIONS.md`
# §6).  A subtly wrong IDF or length normalisation would not crash; it would
# make the learned scorer look better than it is, in the one comparison Stage C
# exists to report.  A published implementation is the cheaper correctness
# argument.
#
# Note for anyone reading a recall table: `retrieve` returns `k` documents
# whether or not they share a term with the query, so a zero score is "no
# lexical overlap" rather than "weakly relevant".  `graft.retrieve.bm25` drops
# non-positive scores for that reason -- see its module docstring.
bm25s==0.3.10
